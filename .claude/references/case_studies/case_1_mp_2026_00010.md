# Case Study 1 — MP-2026-00010 (full purchase-from-zero-stock cycle)

Real document data captured on 2026-08-08, after the flow ran end to end on the `manufact` site.
Kept as a reference for the training manual and for answering follow-up questions about how the
Material Planning → purchase → allocation pipeline behaves. Numbers below are the actual values
from this document, not illustrative examples.

This case is also published in-app: click **"Over all Manual"** on any Material Planning form
(next to the feature-by-feature **"Manual"** button), or go directly to the
`material-planning-case-studies` page. That page covers the same ground as this file (raw material
list + CSV download, weight-calculation worked examples, Consolidate Item required/entered/
purchased table, allocation examples) and will be extended with the Production Plan / Material
Issue Plan sections once those are run for MP-2026-00010, plus a Case 2 entry once that scenario is
built. Source: `production_management/page/material_planning_case_studies/`.

## What this case demonstrates

- Starting state: **zero exact-match stock** for every raw material row (user had removed all
  existing stock reservations before this run).
- All raw material demand fell straight through to **Unavailable Items → Consolidate Item**
  (no Available Raw Materials / Material Mapping rows existed before purchasing).
- **No alternate items were used anywhere** — every Consolidate Item row purchased the original
  planned item itself. This is the baseline/simplest path: it does NOT cover alternate-item
  allocation, Material Mapping, Excess Material Mapping, or partial/split purchasing. Those need
  their own case studies (Case 2, 3, ... as they come up).
- One Material Request → one Purchase Order → one Purchase Receipt covering all 5 consolidated
  items at once → automatic allocation on PR submit puts every row into **Available Raw
  Materials** (never Material Mapping, since nothing was an alternate item).

## Raw Materials → Consolidate Item

61 Raw Material rows (across 15 DUNO/Mark Nos, 1B1–1B15) reduced to **5 Consolidate Item rows**,
deduped purely by `item_code` (drawing/DUNO origin is not a grouping key — see architecture notes
in the main change-request plan).

| Item Code | Group | Required Kg | Purchase dims (L×W×T, Sec Qty) | Purchase Kg | Difference Kg |
|---|---|---:|---|---:|---:|
| PLATE10 | Plates | 302.85 | 500 × 500 × 3 mm, 52 Nos | 306.15 | 3.30 |
| ISA100 | Structurals | 1530.528 | 3000 mm, 37 Nos | 1653.90 | 123.372 |
| ISMB400 | Structurals | 23039.402 | 12000 mm, 32 Nos | 23654.40 | 614.998 |
| ISMB450 | Structurals | 4246.432 | 6000 mm, 10 Nos | 4344.00 | 97.568 |
| ISMB250 | Structurals | 1842.46 | 3000 mm, 17 Nos | 1902.30 | 59.84 |

`Difference Kg = Purchase Kg − Required Kg` in every row — this is pure whole-length/whole-piece
purchasing surplus (you can't buy 0.86 of a 12m ISMB400 beam), **not** related to the Excess
Material Mapping/off-cut system. See the manual's Consolidate Item section for the general
explanation; the ISMB400 row here (614.998 Kg surplus) is the same worked example already in the
manual.

## Purchase Order / Purchase Receipt

Both PO and PR carry all 5 items with the exact `Purchase Kg` quantities above (rate left at 0 —
zero-valuation test/internal receipt). PR received qty matches ordered qty exactly (no
under/over-receipt in this case — that's a scenario still to be captured separately).

## Resulting allocation (after PR submit)

- `Unavailable Items`: 61 → **0**
- `Consolidate Item`: still **5 rows**, unchanged — this table is a purchasing record, it is never
  auto-cleared after receipt (see manual note).
- `Available Raw Materials`: **0 → 43 rows**, one row per original Unavailable Item row that had a
  batch-tracked item (some of the 61 raw material rows share the same DUNO/item combination and
  collapsed during allocation matching — 43 is the count of distinct required-row allocations, not
  61).
- `Material Mapping`: **0 rows** — expected, since no alternate item was purchased in this case.

Batches created/consumed by this receipt:

| Item Code | Batch |
|---|---|
| PLATE10 | `PLT10-T3-L500-W500-R006` |
| ISA100 | `ISA100-L3000-R006` |
| ISMB400 | `ISMB400-L12000-R006` |
| ISMB450 | `ISMB450-L6000-R006` |
| ISMB250 | `ISMB250-L3000-R006` |

Every Available Raw Materials row for a given item code points at that same single batch (one
batch per item code from this receipt), with `shortfall_qty = 0.0` across the board — full
requirement met, no partial allocation needed in this case.

## Open follow-ups for later cases

- This case has no alternate-item purchase → doesn't exercise the Material Mapping /
  `reserve_without_dimensions` / `allocate_based_on_sec_qty` auto-set behavior on PR submit.
- No partial/under-receipt → doesn't exercise the sequential shortfall-on-last-row allocation
  rule (Phase 2.5 of the change-request plan).
- No Excess Material Mapping activity in this MP.
